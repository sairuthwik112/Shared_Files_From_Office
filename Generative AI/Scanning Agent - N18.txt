Step 1: What problem are we trying to solve?

The RSS feeds contain messy, unstructured data.

Example:

Dell Inspiron Laptop - Save $300. Original Price $850. Now $550.

This is text that humans can understand but computers cannot easily work with.

We want to convert it into a structured format like:

Product = Dell Inspiron Laptop
Price = $550
URL = xyz.com

This process is called:

Unstructured Data → Structured Data

Step 2: What is Structured Output?

Normally an LLM returns natural language.

Example:

"The Dell Inspiron laptop is available for $550."

This is readable but difficult for a program to use.

With Structured Outputs, we tell the LLM:

"Don't give me a sentence. Give me data in a specific format."

Example:

Description
Price
URL

Now Python can easily use these values.

Step 3: How does Structured Output feel?

It feels like:

We create a Python class.
We send the class to GPT.
GPT directly fills the class.
We get back a Python object.

Almost like GPT understands Python objects.

This is how it appears to us.

Step 4: What actually happens internally?

The reality is simpler.

The class is converted into a JSON Schema.

The JSON Schema tells GPT:

"You must return data in this format."

GPT then generates JSON instead of natural language.

OpenAI automatically converts that JSON back into a Python object.

So the flow is:

Python Class

↓

JSON Schema

↓

GPT generates JSON

↓

OpenAI converts JSON

↓

Python Object

Step 5: What is Pydantic?

Pydantic is a library used to define data structures.

Think of it as a way to define a form.

Example:

A Deal must contain:

Description
Price
URL

Pydantic generates rules for this structure.

These rules become the JSON Schema.

Step 6: Understanding the Deal Class

The first class is:

Deal

Think of it as:

One Product Deal

A Deal contains:

Product Description
Price
URL

Example:

Deal

Description = Dell Laptop

Price = 550

URL = dealnews.com/abc

One deal = one product.

Step 7: Understanding the DealSelection Class

The prompt asks GPT:

"Find the best 5 deals."

A single Deal can only store one product.

We need something to store all 5 products.

That's why DealSelection exists.

Think:

DealSelection

contains

Deal 1
Deal 2
Deal 3
Deal 4
Deal 5

So:

DealSelection = Collection of Deals

Step 10: Creating the Prompt

The prompt tells GPT:

"Find the best 5 deals."

The prompt also warns GPT:

Do not confuse:

"$500 Off"

with

This is called Prompt Engineering.

Step 11: Why Field Descriptions Matter

Inside the Deal class, each field has a description.

Example:

Price field:

"Use the actual product price."

Why?

Suppose GPT sees:

Original Price = $800

Discount = $250

Current Price = $550

Without instructions GPT may choose:

$250

which is wrong.

The descriptions guide GPT.

Intelligent Parsing with LLMs and Scanner Agent Workflow
1. Main Idea

The instructor highlights one of the most powerful capabilities of LLMs:

Turning unstructured data into structured data.

Example:

Unstructured text:

"$100 off $300"

LLM understands:

Original Price = $300

Discount = $100

Final Price = $200

Traditional parsers struggled with this type of reasoning, but LLMs can understand the meaning behind the text.

2. Why This Was Difficult Before LLMs

Earlier systems relied on:

Rule-based parsers
Regex patterns
Hardcoded conditions
If-else logic

Example:

Parser expects:

"$100 off $300"

But website changes wording to:

"Usually $200 off, but this week only $250 off"

Traditional parser:

Fails
Returns wrong data
Requires new rules

Problems:

Brittle
Hard to maintain
Break when format changes
Expensive to build
3. Why LLMs Changed Everything

LLMs understand meaning instead of exact patterns.

They can read:

Product descriptions
Discounts
Deals
Resumes
Emails
Documents

And convert them into structured formats.

For example:

Input:

"This Samsung TV normally costs $800 but is on sale for $499."

Output:

Product: Samsung TV

Original Price: 800

Current Price: 499

Discount: 301

4. Resume Parsing Example

The instructor worked on resume parsing.

Before LLMs:

A parser needed:

Hundreds of rules
Name extraction logic
Skill extraction logic
Education extraction logic
Experience extraction logic

Different resume formats caused problems.

Now:

LLMs can read almost any resume format and extract:

Name
Skills
Education
Experience
Certifications

Much more easily.

5. Benefits of LLM-Based Parsing
Advantage 1

Handles different wording styles.

Advantage 2

Understands context.

Advantage 3

Needs fewer rules.

Advantage 4

Works on messy data.

Advantage 5

Easy to adapt to new domains.

6. Drawbacks of LLM Parsing

Nothing is perfect.

Cost

API calls cost money.

Latency

Response takes time.

Unpredictability

LLMs can hallucinate.

They may sometimes:

Misread values
Miss information
Return incorrect data
7. Solution: Structured Outputs

The biggest fix is:

Structured Outputs.

Instead of getting random text:

"Looks like a nice TV deal!"

We force the model to return:

{ product_name, price, url, discount }

Benefits:

Consistent format
Easy for applications
Easy validation
Reliable downstream processing
