Modal

Modal is a cloud platform that lets you run Python code either on your laptop or on cloud machines.
The main advantage is that you write normal Python code and Modal handles infrastructure, containers, GPUs and deployment.
Instead of managing servers yourself, Modal automatically creates and manages them.

Why Modal?

Running AI models locally is limited by your hardware.
Modal allows code to run on cloud GPUs.
The same code can be executed locally or remotely with very small changes.

UTF-8 Check

Modal outputs emojis and special characters in logs.
Some Windows systems may not use UTF-8 encoding.
The notebook checks encoding to avoid Unicode errors.
If UTF-8 is not enabled, Python encoding is changed to UTF-8.

Modal Authentication

Modal requires authentication before using cloud resources.
You create:

MODAL_TOKEN_ID
MODAL_TOKEN_SECRET


These are similar to API keys.
They identify your account and allow access to Modal resources.

Modal Token Setup

Generate tokens from Modal dashboard.
Run the token setup command.
If setup fails, tokens can be stored in a .env file.
load_dotenv() loads the credentials automatically.

Modal App

modal.App("hello") creates a Modal application.
Think of it as creating a cloud project.

Modal Image

An image defines the environment that Modal should create.
Example:

Debian Linux
requests package installed


Modal uses this information when creating cloud containers.

Modal Functions

@app.function() marks a function as cloud executable.
The same function can run:

Locally
Remotely

Local Execution

hello.local()
Runs on your laptop.
API sees your laptop's IP address.
Returns your location.

Remote Execution

hello.remote()
Runs on Modal servers.
API sees Modal server IP address.
Returns the location of the cloud server.

Region Selection

Modal allows execution in specific regions.
Example:

region="eu"


Function runs on European servers.
Useful for compliance requirements such as GDPR.

Training Format vs Inference Format
Important Problem
The model was trained on preprocessed data.
Training inputs contained:

Title
Category
Structured information

The model learned this format.
Risk
If inference uses completely different formatting:

Predictions may become less reliable.

Best Practice
Treat inference data exactly like training data.
This is called:
Training-Serving Consistency

Preprocessor
Purpose
Convert raw product text into the same format used during training.
Benefits

More consistent predictions
Better reliability
Better production behavior
Matches training distribution

Observation
In the instructor's example:

Raw text prediction
Preprocessed text prediction

Both returned the same price.
However preprocessing is still considered best practice.

Ephemeral Inference
Meaning of Ephemeral
Temporary execution.
For every request Modal must:

Create machine
Install dependencies
Download models
Run inference
Shut everything down

Problem
Response takes around:

1 minute
Sometimes longer

Not practical for real applications.

Deployment
Idea
Instead of creating everything for each request:
Deploy once.
Reuse many times.
Benefit

Faster requests
Production-ready workflow

Modal Volumes
What Is a Volume?
Persistent storage attached to a deployment.
Think of it as:

Cloud hard drive

Why Use It?
Without a volume:

Model downloaded repeatedly.

With a volume:

Model downloaded once.
Stored permanently.
Reused later.


Model Caching
First Request

Download model
Store model

Future Requests

Load stored model
Skip downloading

Result:

Faster startup


Speed Improvement
Before optimization:

About 60–90 seconds

After caching:

Around 30 seconds

Roughly twice as fast.

Cold Start
A cold start occurs when:

No active container exists.

Modal must:

Create container
Initialize GPU
Load model

This causes startup delay.

Warm Start
A warm start occurs when:

Container already exists.
Model already loaded.

Requests execute much faster.

Modal Auto Sleep
To save money:

Modal automatically shuts down idle containers.

Default idle period:

About 2 minutes

After that the container sleeps.

Consequence of Sleeping
The next request causes another cold start.
The system must:

Wake container
Reload model
Reinitialize resources


Keeping Containers Alive
Possible options:

Keep minimum containers running.
Increase idle timeout.

Benefits:

Faster responses
Fewer cold starts

Trade-off:

Higher cost
