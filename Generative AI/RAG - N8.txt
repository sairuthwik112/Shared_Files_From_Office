✅ ✅ 1. What is RAG?
👉 RAG = Retrieval + Generation

Retrieve relevant data from external sources
Generate answer using LLM

👉 One-line:

Search relevant data first, then generate answer


✅ ✅ 2. Why RAG?
✅ Uses custom data (PDFs, docs)
✅ Gives accurate answers
✅ Reduces hallucination
✅ No need to retrain model

✅ ✅ 3. Components

Embedding Model → Text → Vector
Vector DB (FAISS/Pinecone) → Stores vectors
Retriever → Finds relevant data
LLM → Generates answer


✅ ✅ 4. Phase‑1: INDEXING (Data Preparation)
👉 Done once

Steps:

Load files (PDF, docs)
Extract text
Chunking (split text into small parts)
Convert chunks → embeddings
Store (vector + text in DB)
Create index (for fast search)


👉 Output:

Vector Database ready


✅ ✅ 5. Phase‑2: RETRIEVAL + GENERATION
👉 Done every time user asks

Steps:

User query
Query → embedding
Similarity search
Get Top‑K chunks
Build context
Send to LLM
Generate final answer


✅ ✅ 6. Similarity Search
👉 Compare:
Query vector vs Stored vectors

👉 Using:

Cosine similarity

👉 Higher score = more similar

✅ ✅ 7. Top‑K Retrieval
👉 Select only best K results
Example:
k = 3 → top 3 chunks

✅ Improves:

speed
accuracy
avoids noise


✅ ✅ 8. What happens after similarity?
✅ Retrieve top chunks
✅ Extract text
✅ Send as context to LLM
✅ LLM generates answer

 RAG EVALUATION NOTES

✅ 1. Why we need evaluation in RAG
RAG has two parts:

Retriever (gets chunks)
LLM (generates answer)

If answer is wrong, we need to know:

Is retrieval wrong?
Or is LLM wrong?

So we evaluate both separately.

✅ 2. What is a Test Dataset
A test dataset is like an exam.
It contains:

Question (what user asks)
Correct chunk(s) (what should be retrieved)
Reference answer (correct answer)
Keywords (important terms expected)

Purpose:

To compare expected vs actual output
To measure system performance


✅ 3. Full Evaluation Process (Start to End)

Create test dataset
Take one question
Run RAG system
Retrieve chunks
Evaluate retrieval
Generate answer
Evaluate answer
Repeat for all questions
Take average scores


🔷 RETRIEVAL EVALUATION

✅ Purpose
Check whether the system is retrieving the correct chunks.

✅ What happens
For each question:

Retriever returns ranked list of chunks
We compare with correct chunk(s) from test dataset


✅ Important concept
Retriever uses similarity scores, but:

Similarity score is model’s guess
It may rank wrong chunk at top

So we need evaluation to check correctness.

✅ MRR (Mean Reciprocal Rank)
Meaning:

Checks where the first correct chunk appears

How it works:

Find rank of first correct chunk
Calculate 1 divided by rank

Understanding:

Rank 1 → perfect
Rank 2 → acceptable
Rank 5 → poor

Purpose:

Measures how fast correct chunk is found


✅ NDCG (Normalized Discounted Cumulative Gain)
Meaning:

Checks how well all relevant chunks are ranked

Key idea:

Top ranks are more important
Lower ranks are less important

Purpose:

Measures overall ranking quality


✅ Important Note
MRR and NDCG are calculated:

Per question
Then averaged across all questions

They are NOT calculated for individual chunks.

🔷 ANSWER EVALUATION

✅ Purpose
Check whether the LLM gives the correct answer.

✅ What happens
Compare:

Reference answer (expected)
Generated answer (actual)


✅ Possible cases

Retrieval wrong → answer wrong
Retrieval correct → answer wrong (LLM issue)
Retrieval correct → answer correct (best case)


🔷 WHY BOTH EVALUATIONS ARE NEEDED

Retrieval evaluation:

Checks if correct information is retrieved

Answer evaluation:

Checks if LLM correctly uses that information

Both are needed because RAG has two different components.

🔷 IMPORTANT REALIZATION

Retriever already ranks chunks using similarity,
but this ranking may not be correct.
So:

Similarity score = model prediction
MRR/NDCG = ground truth verification


🔷 WHAT TO DO WHEN MRR/NDCG ARE LOW

Low scores mean:

correct chunks are not ranked properly

We do NOT manually pick chunks.
We improve the system by:

changing chunk size
using better embeddings
increasing top-k
using reranking
using hybrid search
improving data quality

Goal:

correct chunk should appear at top rank


🔷 FINAL SIMPLE UNDERSTANDING

Test dataset → gives correct answers
Retriever → gives predicted chunks
Evaluation → compares both
MRR → checks how early correct chunk appears
NDCG → checks how well chunks are ranked
Retrieval evaluation → checks data quality
Answer evaluation → checks LLM quality

🔷 FINAL ONE-LINE SUMMARY

RAG evaluation is done to ensure that the system retrieves the correct chunks and generates accurate answers, using metrics like MRR and NDCG to measure how well the retriever ranks relevant information.

Advanced RAG Techniques

Advanced RAG techniques include hybrid search, reranking, query expansion, multi-query retrieval, metadata filtering, chunk optimization, and self-reflection mechanisms. These techniques improve retrieval accuracy, ranking quality, and reduce hallucination in production RAG systems.
