                                                            --- Data Preprocessing ---


JSONL + Batch processing = send many AI requests together, get results later, and match them using IDs.

You are ordering food:

Normal way:
Order 1 dish → wait → order next → wait

Batch way:
Write 50 orders on paper (JSONL)
Give it to kitchen at once
Kitchen prepares all and returns (in any order)
👉 You use order numbers (IDs) to organize them.

🔹 1. Goal of Day‑2

Convert raw items → structured outputs using LLM
Process large data using batch instead of single calls
Store results and map back to items


🔹 2. Item → LLM Input

Each item has .full field
.full = complete product description (combined text)
This is sent to LLM as input


🔹 3. System Prompt

Defines output format
Forces structured response

Example:

Title
Category
Brand
Description
Details


🔹 4. Single LLM Call

messages = system + user
user = item.full
completion() → sends request
response → contains generated output
track tokens + cost


🔹 5. Why Batch Processing

Avoid sending requests one by one
Send thousands of requests together
Faster + cheaper + scalable


🔹 6. JSONL Format

JSONL = JSON Lines
Each line = one request
File = multiple LLM requests

Example:
line1 → item1 request
line2 → item2 request

🔹 7. make_jsonl(item)

Converts item → JSON request
adds model + messages
adds custom_id
converts to string using json.dumps()

Important:

custom_id = item.id
used to map results later


🔹 8. Structure of JSONL line

custom_id → unique identifier
method → POST
url → /v1/chat/completions
body → model + messages


🔹 9. make_file(start, end, filename)

Creates JSONL file from items
loops through items
converts each item using make_jsonl()
writes each line into file
adds newline between entries

Output:

jsonl file with multiple requests


🔹 10. Upload File

groq.files.create(file, purpose="batch")
uploads JSONL file to Groq
returns file_id


🔹 11. Create Batch Job

groq.batches.create()
input_file_id → uploaded file
endpoint → chat completions
completion_window → time

Meaning:

Groq processes all requests in file


🔹 12. What "Process Requests" Means

Reads each line
sends to model
generates output
stores results

Each line = one LLM call

🔹 13. Check Batch Status

groq.batches.retrieve(batch_id)
returns status

Status:

validating
running
completed


🔹 14. Get Output File

result.output_file_id
this contains results


🔹 15. Download Results

groq.files.content(output_file_id)
save as results.jsonl


🔹 16. Read Results File

read file line by line
json.loads(line) → convert to dict


🔹 17. Extract Output

custom_id → original item index
response.body.choices[0].message.content → LLM output


🔹 18. Map Results to Items

item_id = custom_id
items[item_id].summary = output

Important:

results may come in random order
custom_id fixes mapping


🔹 19. Validate Results

check if item.summary exists
print missing indexes


🔹 20. Cleanup Data

remove unnecessary fields
item.full = None
item.id = None


🔹 21. Batch Class (Automation)

Batch.create() → splits + creates files
Batch.run() → uploads + starts jobs
Batch.fetch() → downloads + maps results


🔹 22. Full Pipeline Flow

items → make_jsonl()
→ JSONL file
→ upload
→ create batch job
→ process requests
→ results file
→ read results
→ map using custom_id
→ store summary in items


🔹 23. Key Concepts (VERY IMPORTANT)

JSONL = multiple requests in one file
custom_id = mapping key
batch = async processing
results not in order
mapping fixes order
batch is scalable solution
