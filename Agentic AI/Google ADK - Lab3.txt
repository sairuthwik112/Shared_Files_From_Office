Task 2: Build Evaluation Set
What is Evaluation?

Testing an agent automatically.

Instead of manually chatting every time.

Example

Test Question:

Move Bob Jones from pool_estimates to accepted_with_deposit

Expected Result:

Correct transition

Agent Score:

PASS or FAIL

What is an Eval Set?

A collection of test scenarios.

Think:

Interview questions for the agent.

Created:

ledger.evalset.json

Purpose:

Stores evaluation configuration.

What is scenarios.json?

Contains customer test cases.

Examples:

Clark Kent

Ron Weasley

Bob Jones

Each scenario asks the agent to perform actions.

What is session_input.json?

Provides initial environment data.

Think:

Initial database records before testing.

What is eval_config.json?

Defines evaluation criteria.

Contains rubrics.

Task 3: Improve Agent

Now we fix the issues.

Problem 1

perform_consistent_transaction

Not implemented.

Purpose

Move customer safely from one table to another.

Example

Before:

Bob in

pool_estimates

Move To:

accepted_with_deposit

Correct Process

Read Record

↓

Write Record To New Table

↓

Delete Original Record

↓

Success

Logic

Read

↓

Verify Exists

↓

Insert

↓

Delete

↓

Return Success

Why?

Prevents data loss.

Bad Example

Delete first.

Insert later.

If insert fails:

Customer disappears.

Good Example

Insert first.

Delete afterwards.

Problem 2

check_transaction

Not implemented.

Purpose

Verify movement between tables.

Example

Allowed

pool_estimates

↓

accepted_with_deposit

Return True

Allowed

completed_pools

↓

paid_and_closed

Return True

Not Allowed

pool_estimates

↓

completed_pools

Return False

Why?

Prevent business workflow violations.

Problem 3

Too Many Open Tools

Agent originally used BigQuery Toolset.

Problem

Agent could do almost anything.

Leads to mistakes.

Solution

Restrict available tools.

Keep only:

read_table

read_table_all

check_transaction

perform_consistent_transaction

Why?

More control

More predictable decisions

Safer behavior

Better evaluation scores

Updated Instructions

Explicitly explained each table.

Examples:

Contains customer estimates.

accepted_with_deposit

Contains approved estimates with deposits.

completed_pools

Contains finished installations.

paid_and_closed

Contains completed and fully paid projects.

Key Concepts

Scenario = One conversation/test

Rubric = Rule used for scoring

User Simulator = Fake user for testing

PASS = Correct behavior

FAIL = Incorrect behavior

Terraform = Reset environment

Valid Transitions = Checks workflow rules

BigQuery Tables = Business records
