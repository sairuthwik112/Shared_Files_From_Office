AGENTS AS TOOLS (ORCHESTRATION VIA LLM) NOTES

What Problem Are We Solving?

We already have:

Professional Sales Agent
Humorous Sales Agent
Executive Sales Agent

Each agent can write a sales email.

The problem is:

How can another agent (Sales Manager) use these agents?

OpenAI Agents SDK solves this by converting agents into tools.

IMPORTANT IDEA

The agents do NOT disappear.

The agents still write the emails.

The SDK simply wraps each agent inside a tool.

Think of it like:

Tool ↓ Agent ↓ LLM

The tool is only a doorway to the agent.

BEFORE CONVERSION

We have:

Professional Agent Humorous Agent Executive Agent

To use them we must manually call:

Runner.run(Professional Agent)

Runner.run(Humorous Agent)

Runner.run(Executive Agent)

This is orchestration by code.

Python decides which agent runs.

AFTER CONVERSION

We do:

Agent ↓ as_tool() ↓ Tool

Example:

Professional Agent ↓ sales_email_writer_1 Tool

Humorous Agent ↓ sales_email_writer_2 Tool

Executive Agent ↓ sales_email_writer_3 Tool

WHAT DOES as_tool() DO?

The SDK automatically creates a wrapper around the agent.

Conceptually, it creates something like:

Tool Called ↓ Run Agent ↓ Get Result ↓ Return Result

The actual email writing is still performed by the agent.

WHAT HAPPENS INTERNALLY?

When Sales Manager calls:

sales_email_writer_1

The flow becomes:

Sales Manager ↓ sales_email_writer_1 Tool ↓ Professional Sales Agent ↓ GPT Model ↓ Email Generated ↓ Tool Returns Email ↓ Sales Manager

WHY CONVERT AGENTS INTO TOOLS?

Because the Sales Manager can easily use tools.

The SDK's tool calling mechanism already allows agents to:

Discover tools
Call tools
Pass parameters
Receive results

Instead of creating a special agent-to-agent communication system, OpenAI uses the existing tool-calling framework.

KEY CONCEPT

The tool is NOT doing the work.

The agent is doing the work.

The tool only forwards the request.

Think of it like:

Reception Desk ↓ Employee ↓ Work Done

The receptionist does not do the work.

The employee does.
