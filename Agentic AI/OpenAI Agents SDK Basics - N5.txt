What is OpenAI Agents SDK?

OpenAI Agents SDK is a framework that helps us build AI agents easily.

It provides:

Agents
Tool Calling
Memory
Tracing
Streaming

Package name: openai-agents

Important: Do not install "agents" because that is a different reinforcement learning package.

PART 1: AGENT AND RUNNER

Agent

An Agent is an AI assistant with:

Name
Instructions
Model
Tools (optional)

Example:

Name = Jokester Instructions = You are a joke teller Model = gpt-5.4-mini

The Agent only defines behavior.

Creating an Agent does not execute anything.

Runner

Runner is responsible for executing the Agent.

Flow:

User Prompt ↓ Runner ↓ Agent Instructions + User Message ↓ LLM ↓ Response

Example:

"Tell a joke about Autonomous AI Agents"

Runner sends this request to the model and returns the answer.

final_output

final_output contains the final response generated by the model.

Example:

User Request ↓ Agent ↓ Model ↓ final_output

This is the answer the user sees.

to_input_list()

Used to see the complete conversation being sent to the model.

Useful for:

Debugging
Understanding prompts
Viewing conversation history
Checking tool calls

TRACING (OBSERVABILITY)

What is Tracing?

Tracing records everything happening inside the agent.

Think of it as a CCTV camera for your agent.

It records:

User prompt
Model call
Tool calls
Responses
Errors
Execution time

Flow:

User ↓ Trace ↓ Agent ↓ Response

Why Tracing is Important?

Suppose the agent behaves incorrectly.

Without tracing: You don't know what happened.

With tracing: You can inspect every step.

Trace Dashboard

Open:

https://platform.openai.com/traces

You can view:

Prompt
Tool usage
Responses
Latency
Token consumption

STREAMING

Normal Response

Without streaming:

User asks question ↓ Wait ↓ Wait ↓ Whole answer appears

Streaming Response

With streaming:

User asks question ↓ Token appears ↓ Next token appears ↓ Next token appears ↓ Complete answer

Just like ChatGPT typing.

Benefits of Streaming

Faster user experience
User sees output immediately
Better responsiveness

PART 2: TOOLS

What is a Tool?

A Tool is a Python function that the LLM can call.

Without Tools:

Agent can only generate text.

With Tools:

Agent can:

Call APIs
Send notifications
Query databases
Read files
Search external systems

Normal Function

Example:

push(message)

Purpose:

Send a notification using the Pushover API.

Flow:

Message ↓ Pushover API ↓ User Phone Notification

Converting Function into a Tool

Using @function_tool converts a normal Python function into an Agent Tool.

After conversion:

The Agent can discover the function and call it automatically.

Tool Description

Every tool should have a clear description.

Example:

Send the given message to the user as a push notification

This description is very important.

The LLM reads it to understand:

What the tool does
When the tool should be used
What input to provide

How Tool Selection Works

User says:

"Notify the user that the pizza is here"

LLM thinks:

Need to notify user ↓ Search available tools ↓ Found push_tool ↓ Execute tool ↓ Return result

Agent with Tools

Notifier Agent

Responsibilities:

Understand notification requests
Call push_tool
Return final response

Flow:

User Request ↓ Agent ↓ Tool Selection ↓ Tool Execution ↓ Result Returned ↓ Final Response

Tool Calling Lifecycle

User Request ↓ Agent receives request ↓ Agent analyzes request ↓ Agent chooses tool ↓ Tool executes ↓ Tool returns result ↓ Agent creates final answer ↓ User receives response

Tracing with Tools

Trace can also record:

Which tool was selected
What parameters were used
Tool output
Final response

This is very useful for debugging.

PART 3: MEMORY

Problem Without Memory

First Request:

"My name is Ed"

Agent responds correctly.

Second Request:

"What's my name?"

Agent forgets.

Why Does It Forget?

Every Runner.run() call starts a completely new conversation.

Flow:

Run 1 "My name is Ed" ↓ Conversation ends

Run 2 "What's my name?" ↓ No previous context

The model cannot remember.

MEMORY APPROACH 1

Manual Conversation History

After a response, we can retrieve the conversation history.

Then append the next user message.

Then send everything back to the model.

Flow:

Conversation History + New User Message ↓ Send Together ↓ Model Remembers

How It Works

Message 1: "My name is Ed"

Assistant: "Nice to meet you Ed"

Store both messages.

Later:

Add:

"What's my name?"

Now model sees:

User: My name is Ed Assistant: Nice to meet you Ed User: What's my name?

Therefore:

Answer = Your name is Ed.

MEMORY APPROACH 2

SQLiteSession

OpenAI Agents SDK provides built-in memory support.

Instead of manually passing history, use a session.

Session

A Session stores conversation history automatically.

Flow:

Message ↓ Session ↓ Stored

Next Message ↓ Previous Messages Loaded ↓ LLM ↓ Response

Benefits of Session

Automatic memory handling
Cleaner code
Easier maintenance
Scales better

In-Memory Session

Session data exists only while the application is running.

Application Stops ↓ Memory Lost

Useful for testing.

On-Disk Session

Memory is stored in a database file.

Application Stops ↓ Database remains ↓ Memory survives restart

Useful for production systems.

COMPLETE ARCHITECTURE

User ↓ Runner ↓ Agent ↓ LLM

Optional: ↓ Tool Calls

Optional: ↓ Tracing

Optional: ↓ Session Memory

↓ Final Response

QUICK REVISION

Agent = Defines behavior, instructions, model and tools.

Runner = Executes the agent.

final_output = Final response returned by the agent.

to_input_list() = Shows complete conversation history.

trace() = Records everything happening inside the agent.

Streaming = Shows output token by token.

Tool = Function that an agent can execute.

@function_tool = Converts a Python function into an Agent Tool.

Tool Description = Helps the LLM decide when to use a tool.

Notifier Agent = Agent capable of sending notifications through a tool.

Memory = Ability to remember previous conversations.

SQLiteSession = Built-in memory support in OpenAI Agents SDK.

Trace Dashboard = Used to inspect prompts, responses, tool calls, latency and execution flow.

Most Important Interview Point:

OpenAI Agents SDK mainly revolves around 5 concepts:

Agent ↓ Runner ↓ Tools ↓ Tracing ↓ Memory (Session)

If you understand these 5 concepts, you understand the foundation of OpenAI Agents SDK.
